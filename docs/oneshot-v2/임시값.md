# 원샷 v2 임시값 목록

원샷 v2 빌드(2026-11-07)에서 PRD의 열린 질문·정하지 않은 값을 만나, 가장 단순하고 되돌리기 쉬운 쪽을 **임시값**으로 정한 것이다. 이 파일이 다음 고침 바퀴의 입력이다.
한 줄 꼴: **무엇 · 고른 값 · 이유 · PRD 어디**. 코드에서는 「임시」 주석이나 `lib/app-config.ts` 한 곳에서 바꾼다.

**줄 수: 125줄**(아래 절들의 「- 」 줄. 절 이름은 만든 순서를 따름: 0 → 0-1 → ① → ② → ③ → ④ → ⑤ → ⑥ → ⑦ → 오프라인 → AI 자리). 같이 보는 문서: `기록-장치.md`(무엇을 어디에 남기나), `마이그레이션.md`(적용 순서).

**다음 고침 바퀴에서 가장 중요한 다섯**
1. **알림은 바깥 설정이 있어야 실제로 간다**(⑦): 푸시 서명 키 셋(`NEXT_PUBLIC_VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY`·`VAPID_SUBJECT`)·서버 키(`SUPABASE_SERVICE_ROLE_KEY`)·예약 비밀(`CRON_SECRET`)·15분 간격 예약이 없으면 알림은 켜지지 않는다. 푸시 본문 암호화는 새 패키지가 필요할 수 있어 본문 없는 신호만 보낸다. 실제로 보내지는지 시험하지 못했다
2. **오프라인은 할 일 적기만**(오프라인 절): 저녁 기록은 퇴근길에 쓰는데 끊기면 저장이 막힌다(범위를 넓힐지가 가장 큰 열린 질문). 기기 보관함에 글이 평문으로 남고, 새벽 4시를 넘겨 올라간 글은 어제 날짜로 들어간다
3. **먼저 하기를 재는 규칙**(⑤·④): 「제시한 횟수」(같은 날·자리·분야·할 일은 한 번), 분자(넓게 셈), 저녁에도 타이머 탭이 추천하는 것, 급한 때를 가르지 않는 것은 모두 임시다. v8 가설의 값이 이 규칙에 달렸다
4. **부족(채울 시간)과 반대편 계산**(③·④): 처음 정한 비율 기준은 이번 주 안에서만, 기타는 부족에서 뺌, 목표를 세운 주는 목표 기준(PRD 7-4 안의 두 줄이 어긋남). 기타를 부족으로 잡을지는 PM이 정할 자리
5. **할 일 update 권한을 넓힌 것과 DB 시험**(0): 1번 마이그레이션이 `todos`의 고칠 수 있는 열을 넓혀 기존 RLS 통합 시험 두 곳을 바꿨고, 새 표 RLS 시험(`v2-rls.test.ts`)과 함께 **DB가 없어 한 번도 돌리지 못했다**. 적용 뒤 `npm run test:rls`부터 돌릴 것

- 범위 · **할 일 적기만**. 끝냄 체크·고치기·지우기·작업 기록·저녁 기록·타이머·분야 더하기는 연결이 있어야 함(끊기면 안내) · PRD 10절 열림(할 일만인지 작업 기록·저녁 기록까지인지). 저녁 기록은 퇴근길에 쓰므로 끊김이 잦을 수 있다는 PRD의 [AI 판단]이 있어 **다음 바퀴 1순위 후보**
- 방법 · 새 패키지 없이 브라우저 localStorage에 사용자별 「보관함」(`lib/outbox.ts`): 못 올린 할 일(연결 대기·저장 중·실패)을 기기에 두었다가 연결되면 같은 id로 다시 보냄(서버가 같은 id는 한 번만 만듦). 올라가면·뺀 줄이면 지움. IndexedDB·Background Sync는 쓰지 않음 · 가장 단순
- 기기에 글이 평문으로 잠깐 남음 · 서버에는 암호화해 두지만 기기 보관함은 평문(옛 판의 D6 「저장 전 글을 기기에 두지 않는다」를 PRD 10절이 바꿈). 로그아웃하면 지움. 공용 기기·기기 분실 위험은 [미확인] · 22에게 받을 것
- 줄 모양 · 끊긴 채 적으면 줄이 「연결되면 저장해요」로 남고(체크 칸·자세히 없음, 「빼기」 있음), 글 칸은 비워짐. 못 올린 줄이 보관함에서 되살아날 때도 같은 모양 · 입력이 끊기지 않게
- 적은 때(날) · 서버는 기기가 보낸 적은 때(writtenAt)가 **최근 72시간 안·미래 5분 이내**일 때만 그 때의 두노 하루로 넣고, 아니면 서버 시계를 따름 → 위조 가능한 범위를 72시간으로 막음. 새벽 4시를 넘겨 올라간 어제 글은 오늘 목록에서 보이지 않음(어제 날짜로 들어감) · 계측의 저장 시각(G9)과 기록 위조 막기(22 4-3, 서버 시각)를 맞추는 방법. 22에게 받을 것
- 저녁 기록의 저장 시각 · 이번 범위가 아니라 서버 시각(DB 기본값)과 기기 시각을 둘 다 이미 남김(②). 저녁 기록을 오프라인으로 넓힐 때 그대로 쓸 수 있음
- 앱 껍데기 오프라인 · **이미 연 채 끊긴 경우만** 다룸. 끊긴 채 앱을 새로 여는 것은 서비스 워커가 화면 HTML을 저장하지 않아(개인 데이터가 캐시에 남지 않게) 오프라인 안내 화면이 뜸 · 기존 설계 유지, 화면 HTML 캐시 여부는 PM 결정 필요 [미검증]
- 보관함 크기 · 사용자 기기당 100개까지(서버 하루 200개 상한과 별개) · 임시
- 기기 시계가 틀린 경우 · 적은 때가 72시간 밖이면 서버 시계의 하루로 들어감(날이 어긋날 수 있음) · 임시
