# 원샷 v2 마이그레이션 목록과 적용 순서

**개발용 DB에는 1~10번이 모두 적용돼 있다.** 1~9번은 원샷 v2 앞 바퀴에서 창구가 적용했고, 10번은 11-08 PM이 직접 `db push`했다. 11-09 00:25에 `supabase migration list`로 1~10번이 원격 이력에 모두 있음을 확인했다(`migration list`는 읽기만 한다). 이 빌드(코드 변경)는 마이그레이션을 새로 적용하지 않는다. 다른 DB(운영 등)에 적용할 때는 창구가 따로 한다. 모두 **더하기만** 한다(새 표·새 열·새 권한·새 트리거. 기존 열·데이터는 바꾸거나 지우지 않는다). 파일 이름의 시각 순서가 곧 적용 순서다.

**먼저 적용하고 나서 앱을 배포한다.** 앱이 새 열(`todos.position`)과 새 표를 바로 읽는다. 적용 전에 배포하면 할 일 목록 읽기가 실패한다.

**순서 · 파일 · 무엇을 더하나 · 앞 파일에 기대는 것**
1. `20261107100000_todo_manage.sql` · `todos.position` 열, `todos (id, user_id)` 고유 제약, `todos` update 권한을 `done`에서 `done·text_encrypted·category_id·position`으로 넓힘 · (없음)
2. `20261107100100_todo_notes.sql` · `todo_notes` 표(작업 기록), RLS, 개수 상한 트리거 · 1번의 고유 제약
3. `20261107100200_user_settings.sql` · `user_settings`(처음 설정·알림 설정), `category_ratios`(처음 정한 비율) 표, RLS · 기존 `categories (id, user_id)` 고유 제약
4. `20261107100300_evening_logs.sql` · `evening_logs` 표(저녁 기록, 쌓기만), RLS, 상한 트리거 · (없음)
5. `20261107100400_view_events.sql` · `view_events` 표(화면 본 것, 쌓기만), RLS, 상한 트리거 · (없음)
6. `20261107100500_focus_sessions.sql` · `focus_sessions` 표(타이머·먼저 한 기록), RLS, 상한 트리거 · 기존 `categories (id, user_id)`
7. `20261107100600_todo_offers.sql` · `todo_offers` 표(할 일 제시), RLS, 상한 트리거 · 기존 `categories (id, user_id)`
8. `20261107100700_weekly_goals.sql` · `weekly_goals` 표(이번 주 목표), RLS · (없음)
9. `20261107100800_push_subscriptions.sql` · `push_subscriptions` 표(푸시 구독), RLS, 상한 트리거 · (없음)
10. `20261107110000_ratio_other.sql` · **(고침 3바퀴)** `user_settings.ratio_other_percent` 열(처음 정한 비율의 기타 몫)과 그 열의 insert·update 권한 · 3번의 `user_settings` 표. **없어도 앱은 돈다**(열을 못 읽으면 기타 몫 없음으로 읽는다). 기타를 비율에 넣은 사용자의 저장만 이 파일이 있어야 한다. **개발용 DB에 적용함**(11-08 PM이 직접 `db push`. 23:05:33은 push한 시각이 아니라 `migration list`로 원격 이력에 10번이 있음을 확인한 시각이다. push 시각은 따로 기록하지 않았고 그 확인보다 앞이다). 되돌림 파일: `supabase/rollback/20261107110000_ratio_other.down.sql`

**고침 3바퀴 2부(기기 먼저 저장)에는 새 마이그레이션이 없다.** 쓰는 열이 모두 이미 있다(`client_started_at`·`client_saved_at`·`todos.day`·`todo_notes.day` 등). 위 10번은 1부의 기타 비율용이고, 없어도 앱은 돈다.

## 확인할 것
- **주의(권한 변경)**: 1번이 `todos`의 update 권한을 넓힌다. 기존 RLS 통합 시험 두 곳(`tests/integration/rls.test.ts`·`categories-rls.test.ts`)이 「update는 done만」을 단언하고 있어서 새 권한에 맞춰 바꿨다. 둘 다 DB가 없어 **돌려 보지 못했다**.
- 새 표의 RLS 시험은 `tests/integration/v2-rls.test.ts`에 있다(**미실행**). 적용 뒤 `npm run test:rls`로 돈다. 쌓기만 하는 표라 시험 행이 남는다(그 파일 머리의 SQL로 지운다).
- 개수 상한 값(분야 50, 작업 기록 20000, 저녁 기록 20000, 본 것 100000, 타이머 50000, 제시 50000, 푸시 구독 20)은 모두 임시다.
- 알림을 실제로 보내려면 마이그레이션 말고도 **서버 설정**이 필요하다(푸시 서명 키·서버 키·예약 비밀·예약 실행). `docs/oneshot-v2/임시값.md` ⑦ 참고.
- 되돌림 파일(down)은 10번만 있다: `supabase/rollback/20261107110000_ratio_other.down.sql`. 10번을 되돌릴 때만 손으로 돌리고(`db push`는 이 폴더를 올리지 않는다), 돌리면 기타 몫 값이 사라지니 그 열을 쓰는 코드를 먼저 뺀다. 나머지는 되돌림 파일이 없다: 새 마이그레이션으로 되돌리고, 코드를 먼저 뺀다.
